# Лабораторная работа №1, Go

Умножение двух квадратных матриц без готовых библиотек. Есть последовательный вариант и вариант с goroutine.

## Файлы

- `main.go` — запуск программы, параметры командной строки и подсчёт среднего времени.
- `matrix.go` — матрица, заполнение случайными числами и сравнение результатов.
- `multiply.go` — умножение по строкам и столбцам, разбиение результата на блоки и многопоточное вычисление.
- `go.mod` — описание Go-модуля.

Матрица хранится в одном массиве. В параллельном варианте матрица результата делится на прямоугольные блоки. Каждый блок считает отдельная goroutine. Блоки не пересекаются, поэтому дополнительных блокировок не требуется. Главная goroutine ждёт окончания всех работников через `sync.WaitGroup`.

## Компьютер

Intel Core i5-13500H, 12 физических ядер, 16 логических ядер, Windows 11.

## Запуск

Откройте PowerShell в этой папке и выполните:

```powershell
go run . -mode sequential
go run . -mode parallel
```

Размер матриц по умолчанию — 1000 x 1000. Для каждого варианта программа делает 10 замеров и выводит среднее время. В параллельном режиме проверяются 1, 2, 4, 8, 16, 32 и 64 worker.

Примеры изменения параметров:

```powershell
go run . -mode parallel -size 800 -runs 5
go run . -mode parallel -size 1000 -workers 4,8,16,32,64 -runs 10
```

После установки Go, если команда `go` не находится в текущем окне PowerShell, выполните:

```powershell
$env:Path = 'C:\\Program Files\\Go\\bin;' + $env:Path
```

Затем проверьте:

```powershell
go version
```

## Результаты

Для матриц 1000 x 1000 сделано по 10 запусков.

Последовательный режим:

| Обход | Среднее время |
| --- | ---: |
| По строкам | 2.928694 с |
| По столбцам | 3.035877 с |

Параллельный режим:

| Число worker | Среднее время | Ускорение |
| ---: | ---: | ---: |
| 1 | 2.476245 с | 0.96x |
| 2 | 1.267968 с | 1.87x |
| 4 | 0.714003 с | 3.31x |
| 8 | 0.505790 с | 4.68x |
| 16 | 0.503849 с | 4.69x |
| 32 | 0.510546 с | 4.63x |
| 64 | 0.529164 с | 4.47x |

В параллельном тесте среднее время последовательного эталона составило 2.365027 с. Все результаты совпали с эталоном. Лучшее среднее время получилось при 16 worker. При 32 и 64 worker ускорение уже не растёт из-за накладных расходов на планирование goroutine.
